# real-problems

一个专为 AI 编码助手（Agent）设计的文档治理工具（Skill）：针对已保存在本地磁盘上的 **AI 提示词/工作流**、**工程架构规范**、**运维与业务操作手册（SOP）**、**报告、稿件或专利草稿**，通过项目实际代码与环境，或用户提供的模板、证据、图表和附图进行多角度审查，找出真正影响完成条件的硬伤（真问题），再由人工闸门决定保留清单或精准修改。

---

## 核心特性

- **独立评审（独立陪审团）**：默认派出 3 名评审者，各在独立上下文里拿相同的完整输入跑完整轮评审，彼此不通气。**是否分派不同模型由用户在闸门中自主决定**：若选择分派不同模型，盲区不重叠，同一处被不同模型独立指出即为高置信信号；若选择单一模型，则统一使用相同模型。也可切换为「分区覆盖」模式，按完成条件切成互不重叠的角度分头审查，保证不漏检。
- **只抓真问题**：拒绝模棱两可的主观润色，只处理“能指到具体位置、且不改必定导致规则失效、与项目实际脱节或执行死锁”的硬缺陷。同类实现有、但本对象并不要求的产品缺口一律淘汰。
- **区分用户指定改动**：改名、改 description 这类用户已拍板的诉求不需要论证，与真问题分开记录，但必须带影响面清单（目录名、frontmatter、README、引用）并在最后一步原子改完，不会只改一半留下断链。
- **项目现实深度对照（调研）**：规则与 SOP 对照项目代码、配置和环境；报告、稿件与专利草稿对照用户提供的 brief、模板和核对材料。也可对标成熟规范寻找遗漏分支；调研发现的新标准仍须经人批准，才能升格为判据。
- **挑刺强制独立上下文**：挑刺拿到改法稿、获批清单和核对所需材料，但拿不到写方案时的推理过程；根据用户确定的模型策略分派不同模型或相同模型。避免作者带着完整上下文当自己的红队。
- **人工闸门把关**：调研/模式/模型分派、清单、最终方案三道闸门均发出选项由人点选；超时未选则用推荐项，并记入笔记。绝不跳过表单代选。
- **快照与精准修改**：修改前自动在系统临时目录备份快照，修改后严格比对 diff 并验证问题消除，不夹带任何方案外改动。

## 适用与不适用场景

### ✅ 适用对象

1. **AI 提示词、技能与工作流**
   - Agent Skill 技能定义文件（如 `SKILL.md`）
   - 系统提示词（System Prompt）、输出格式约束模板
   - 多 Agent 协作与状态转移路由、评测标准（Eval Rubrics）
2. **系统架构与工程规范**
   - Agent 指引与项目规则（`AGENTS.md`、`.cursorrules`）
   - 架构决策记录（ADR）
   - 团队代码规范、MR 合入清单、API 接口数据契约
3. **运维、安全与业务操作手册**
   - 应急止血预案（Runbook）、数据库割接/迁移 SOP、灾备演练说明
   - 生产环境发布清单、环境搭建手册、权限审计规范
   - 带有明确验收准则（AC / Given-When-Then）的产品与测试规格
4. **已有报告、稿件与专利草稿**
   - 各类已有报告
   - 技术、业务、研究、科普、新闻、演讲、宣传、文学与创意等已有稿件
   - 已有技术交底书、专利申请文件或答复草稿

### ❌ 不适用场景
- **代码运行时报错排查**：请使用常规排查工具或排查类 skill（如 `diagnosing-bugs`）。
- **产品与业务需求讨论**：请使用需求评审工具（如 `grilling`）。
- **从零新建 Skill**：请使用 `create-skill`。
- **代码架构重构与拆模块**：请使用代码设计类工具（如 `codebase-design`）。
- **从零代写或无定位整篇重写报告、稿件、专利申请**：本 Skill 只审查已有文件中的可定位问题。

## 安装与使用

### 1. 安装

在命令行中执行：

```bash
npx skills add Shengjingwa/real-problems-skill
```

> **注意**：
> - 本仓库内的 `skills/real-problems/` 即为 Skill 本体，目录名必须保持为 `real-problems`（与 `SKILL.md` 中的 `name` 一致）。
> - 运行过程中产生的记录笔记会自动保存在本仓库的 `docs/` 目录下（已在 `.gitignore` 中忽略，不提交到 git）。

### 2. 使用

在 Cursor 中新建对话，输入斜杠命令即可调用：

```text
/real-problems
```
