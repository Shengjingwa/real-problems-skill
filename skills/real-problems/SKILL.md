# real-problems

## 对象

只改已经在磁盘上、且属于下面一种的文件：

- agent skill
- 给 agent 看的说明（`AGENTS.md`、规则、路由）
- 给人看的手册、runbook、发布步骤

第 1 步跟一遍对象里的文件指针。看包含指针的完整句子及所属条目：其中明确要求修改目标文件，且目标已存在、属于上面三种时，列入对象、读全；其余指针只按原指令读取、核查或参照目标，不列入、本次不改。

对象是 skill 时：主 agent 与每个 subagent 在交稿或改文件之前读 `writing-for-agents` 和 `SKILL-MECHANICS.md`。

对不上：结束本次，只报告该改走哪条（运行时排错 → 排查类 skill；产品取舍 → `grilling`；从零新建 → `create-skill`；代码拆模块 → `improve-codebase-architecture`）。不调用那条。

对象没写明可检验的完成条件：结束本次，说明无法按真问题继续。

## 真问题

同时满足：

1. **能指到**：对象里的位置、原文或行为
2. **不改就失败**：不改则对象达不到它自己写明的完成条件

id、斜杠命令、description 只有人点名要改时才收进清单。

## 1. 定对象

读列入对象的每一份全文。记下路径、它自己写明的完成条件、人声明这次不动的部分。

跟一遍每份对象里的文件指针，按「## 对象」的界限列入或记下不列入的理由；列入的当场读全。

**完成：** 每个列入的路径存在且属于三种之一；完成条件摘自原文；每个文件指针要么已列入并读全，要么记下不列入的理由。

## 2. 闸门：调研

AskQuestion 一题多选（推荐项在前并标 `(Recommended)`），选项就这三个：

- 核查对象自己引用的东西是否成立：命令、路径、目录名、别的 skill 名
- 其它（人自己填）
- 不调研

发完即停，等回复。勾了「不调研」就忽略其它勾选，往笔记「调研」节记一行理由，进下一步。

实际执行「其它（人自己填）」前，先检查核查目标是否清楚、所需来源在当前环境中是否可访问、核查动作是否可执行；任一不满足，用 AskQuestion 指明缺口，让人补清、换项或改选「不调研」。发完即停，等回复。

勾了种类：先为每种调研列核查清单，每项写编号、对象绝对路径和原文位置；第一项的清单覆盖每份对象里的全部命令、路径、目录名和别的 skill 名。清单过长时按对象分批，并行派 subagent，最后合并成每种一份回报。

任务只给这一批清单、这一种调研、源码仓绝对路径、与清单位置相交的人声明不动部分；调研直接核查完成条件时，再给对应条件。subagent 按路径读取核查所需的原文；只有核查涉及整份对象时才读全文。相对路径和仓库内命令以源码仓为基准核查。清单每项回报：事实、一手来源、与对象原文哪一处出入。调研只补事实，不给对象新增完成条件。

**完成：** 人做出选择；选「不调研」则笔记里有那行理由；实际执行「其它（人自己填）」前，核查目标清楚、所需来源可访问、核查动作可执行；勾了种类则核查清单覆盖该种全部目标，每项正好一条字段齐全的结果，每种正好一份合并回报。

## 3. 派角度

主 agent 定 2–4 个角度：第 1 步记下的每条完成条件，正好归给一个角度。各角度并行；一个角度的材料需要分批时可派多个 subagent，最后合并成一份角度回报。

先按每条已分配完成条件列输入：条件所在对象、条件直接指向的对象、点名这些对象原文位置的调研事实，以及相交的人声明不动部分。对象写绝对路径，并标明哪些须读全文。每个任务只给这一个角度和本批输入；同一条完成条件及其输入放在同一批。subagent 按路径读取，标明须读全文的对象在交稿前读全。模型从手头可用的里派。

每条候选写：位置及原文、对应哪条完成条件、不改时能看见的失败。该角度无候选就写「无候选」。

**完成：** 角度 2–4 个；第 1 步记下的每条完成条件正好归入一个角度和一个批次，其所在对象、直接指向的对象和相关调研事实在同一批输入中；每个角度一份合并回报；每条候选三字段齐全，或该角度为无候选。

## 4. 筛真问题

先给每条候选唯一编号。合并同因同果的候选，合并后的候选也编号并记录全部来源候选编号。冲突的用对象原文裁决。只留真问题。未留下的各写一句丢弃原因。

先给每条调研事实唯一编号。调研事实要写成候选才进清单；写成候选时给候选编号并记录来源事实编号。写不成候选的按事实编号记进笔记「调研」节；撞上人声明不动的部分也按事实编号记进去，注明撞上了什么。

写入笔记，并记录终点去向：每个候选编号最终对应一个清单编号或一条丢弃原因；每个调研事实编号写成候选时沿该候选到同类终点，未写成候选时对应一条「调研」节记录。每个编号正好一个终点，不能只停在另一个候选编号。把清单和丢弃原因放进下一闸门 AskQuestion 的 `prompt`。

**完成：** 终点去向覆盖每个候选编号和调研事实编号，每个编号正好一个终点；清单每条都同时满足「## 真问题」那两条。

## 5. 闸门：真问题

AskQuestion 一题两选项（推荐项在前并标 `(Recommended)`）：按这份清单继续 / 停。发完即停，等回复。

**完成：** 人选择继续。此后只处理最近一次获批清单；清单条目的身份、语义或范围发生变化，包括增、删、合并、拆分或语义改写时，回到第 4 步更新清单并重新过本闸门。不改变语义的排版或错字修正不算清单变化。

## 6. 改法与异议

先后两个 subagent，只交稿。任务都给：对象全文、完成条件、人声明不动的部分、获批清单。

1. **写改法**：每项交：对应哪条获批真问题；改哪（精确到标题和原句）；具体怎么改（给出可直接采用的措辞；无法逐字预写时，给出能唯一判断改后结果的语义修改说明）；允许改动的边界；改后哪项可观察失败应消失、为何对应完成条件会重新成立；风险；故意不改什么。每条获批真问题至少一项改法。
2. **挑刺**：另给改法稿。交对不上清单的、会破坏完成条件的、漏掉获批条的、超出清单的。替代方案也写成异议。

主 agent 写成最终方案：保留每项改法的全部字段；每一改只对着清单一条；每条获批真问题至少一项改；每条异议写明采纳后怎么改，或依据哪段原文驳回。写入笔记，并把方案和异议的处置放进下一闸门的 `prompt`。

**完成：** 问题与改法双向对齐；每条异议有处置。

## 7. 闸门：最终方案

AskQuestion 一题两选项：按这份方案改对象 / 停。发完即停，等回复。

**完成：** 人选择按最近一版方案改。此后方案的位置、具体改法、允许改动边界、预期结果、风险或故意不改内容等任一实质字段发生变化时，回到第 6 步更新最终方案和异议处置，并重新过本闸门；变化涉及清单时，先按第 5 步重新批准清单。不改变语义的排版或错字修正不算方案变化。

## 8. 改对象

进入本步后、编辑前，在系统临时目录创建本轮唯一目录；无损保存每份对象的当前全文，并用清单记录对象绝对路径与快照的对应关系。快照包含本轮开始前已有的工作区改动。

只改方案点名的位置。改完后只比较对象当前全文与对应快照；笔记和其它工作区文件不纳入本轮对象 diff。本步完成或停止时清理临时目录。

**完成：** 按最终方案每一改的具体改法、允许改动边界和预期结果逐项核对：本轮对象 diff 覆盖方案每一改且没有方案外对象改动；每条真问题对应的可观察失败已消失；对象原完成条件仍成立。

## 笔记

写到源码仓 `docs/<父目录名>-<文件名>.md`。不论从哪个工作区召回，都写这里。

定位源码仓，按顺序取第一个成立的：

1. 当前工作区根目录名是 `real-problems-skill`：工作区根就是源码仓。
2. 本 skill 目录里有 `source-root`：取第一行的绝对路径。
3. 都不成立：问人要源码仓的绝对路径，发完即停，等回复；拿到后先把这一行写进本 skill 目录的 `source-root`，再用它继续本次。

`source-root` 是本机文件，不随仓库分发。
