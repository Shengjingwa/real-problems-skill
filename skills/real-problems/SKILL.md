# real-problems

## 对象

只改已经在磁盘上、且属于下面一种的文件：

- agent skill
- 给 agent 看的说明（`AGENTS.md`、规则、路由）
- 给人看的手册、runbook、发布步骤

这次要改到的被指向文件，同样必须已存在、属于上面三种，并在第 1 步列入对象、读全。

对象是 skill 时：主 agent 与每个 subagent 在交稿或改文件之前读 `writing-for-agents` 和 `SKILL-MECHANICS.md`。

对不上：结束本次，只报告该改走哪条（运行时排错 → 排查类 skill；产品取舍 → `grilling`；从零新建 → `create-skill`；代码拆模块 → `improve-codebase-architecture`）。不调用那条。

对象没写明可检验的完成条件：结束本次，说明无法按真问题继续。

## 真问题

同时满足：

1. **能指到**：对象里的位置、原文或行为
2. **不改就失败**：不改则对象达不到它自己写明的完成条件

id、斜杠命令、description 只有人点名要改时才收进清单。

## 1. 定对象

读列入对象的每一份全文。记下路径、它自己写明的完成条件、人声明这次不动的部分。

**完成：** 每个列入的路径存在且属于三种之一；完成条件摘自原文。

## 2. 派角度

主 agent 定 2–4 个角度：合计覆盖全部完成条件，边界不重叠。并行各派一个 subagent。

每个任务给：对象全文、完成条件、人声明不动的部分、是否点名改名、这一个角度。模型从手头可用的里派。

每条候选写：位置及原文、对应哪条完成条件、不改时能看见的失败。该角度无候选就写「无候选」。

**完成：** 每个角度一份回报；每条候选三字段齐全，或该角度为无候选。

## 3. 筛真问题

合并同因同果的候选。冲突的用对象原文裁决。只留真问题。未留下的各写一句丢弃原因。

写入笔记，并把清单和弃选理由放进下一闸门 AskQuestion 的 `prompt`。

**完成：** 每个候选要么进清单要么有丢弃原因；清单每条过两条杠。

## 4. 闸门：真问题

AskQuestion 一题两选项（推荐项在前并标 `(Recommended)`）：按这份清单继续 / 停。发完即停，等回复。

**完成：** 人选择继续。此后只处理这份获批清单；若证据要推翻或补充清单，回到第 3 步并重新过本闸门。

## 5. 改法与刺

先后两个 subagent，只交稿。任务都给：对象全文、完成条件、人声明不动的部分、获批清单。

1. **写改法**：交改哪、为何能让对应完成条件重新成立、风险、故意不改什么。每条获批真问题至少一项改法。
2. **挑刺**：另给改法稿。交对不上清单的、会破坏完成条件的、漏掉获批条的、超出清单的。替代标成刺。

主 agent 写成最终方案：每一改对着清单一条；每条获批真问题至少一项改；每条刺写明采纳后怎么改，或依据哪段原文驳回。写入笔记，并把方案和刺的处置放进下一闸门的 `prompt`。

**完成：** 问题与改法双向对齐；每条刺有处置。

## 6. 闸门：最终方案

AskQuestion 一题两选项：按这份方案改对象 / 停。发完即停，等回复。

**完成：** 人选择按方案改。

## 7. 改对象

只改方案点名的位置。

**完成：** diff 覆盖方案每一改、没有方案外改动；每条真问题对应的可观察失败已消失；对象原完成条件仍成立。

## 笔记

写到源码仓 `docs/<父目录名>-<文件名>.md`。不论从哪个工作区召回，都写这里。

定位源码仓：当前工作区根目录名是 `real-problems-skill`；否则读本 skill 目录里的 `source-root`（一行绝对路径）。找不到就停，问路径。
